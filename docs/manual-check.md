# 手動確認チェックリスト（フェーズ 3）

自動テストの対象外の層を確認する。`enigo` アダプタ、ホットキー登録、実モニター取得、環境検査。
起動は `bun run tauri dev`（`src-tauri/` で `cargo build` が通ること）。
開発ビルドでは、アプリのイベントが標準エラーに `[auto-clicker] ...` として出る。
前のインスタンスが残っていると、ホットキーが競合して登録に失敗する。終了してから起動すること。

現状の実行内容は仮で、「現在位置を左クリック、200 ms 間隔、手動停止」。UI（フェーズ 6）で置き換わる。

## Windows
- [x] 起動して、ホットキー登録が成功する（開発ビルドの標準エラーに `hotkeys: toggle=true capture=true`）
- [x] 電卓などの上にカーソルを置いて F6 を押すと、クリックが始まる（Windows 11、ユーザー確認済み）
- [x] もう一度 F6 を押すと止まる。止まった後にクリックが続かない（Windows 11、ユーザー確認済み）
- [x] F7 でカーソル位置が `captured` イベントで返る（キー送信時のカーソル (1222, 713) とログが一致）
- [x] 他のアプリが F6 を使っている状態で起動すると、登録に失敗する（前のインスタンスが残った状態で起動し、`toggle=false capture=false` を確認）
- [x] 登録に失敗した状態で、開始が拒否される（Controller の単体テストでは確認済み。実アプリでは UI ができ次第）
- [x] 固定座標・ダブルクリック・長押し・右/中ボタンが期待どおりに動く（UI ができ次第）
- [x] 画面外の座標が入った Sequence は開始前に拒否される（UI ができ次第）
- [x] 実行中にモニター構成を変えたら停止する（フェーズ 4）
  - 手順: F6 で開始 → 設定の「ディスプレイ」で解像度（または拡大率）を変える
  - 期待: 約 0.5 秒以内にクリックが止まり、標準エラーに `ScreenLayoutChanged` → `State(Idle)` → `Finished(Cancelled ...)` の順で出る
  - 元の設定に戻して、もう一度 F6 で開始できる（新しい構成が基準になる）

## トレイと起動（フェーズ 7）
自動確認済み（デバッグビルドの exe を実際に起動して確認）:
- [x] 通常起動でウィンドウが出る
- [x] 2 つ目を起動すると、そのプロセスはすぐ終了し、最初のプロセスは動き続ける
- [x] × ボタン（WM_CLOSE）では、プロセスが残り、ウィンドウだけ隠れる
- [x] 隠れた状態で 2 つ目を起動すると、ウィンドウが再表示される
- [x] 「ウィンドウを出さずにトレイで起動」がオンだと、起動時にウィンドウが出ない（process は動作）

手動で確認が必要（トレイとレジストリは自動で操作できない）:
- [x] タスクトレイにアイコンが出る。左クリックでウィンドウが開く
- [x] 右クリックのメニューが「開始」「ウィンドウを表示」「終了」の 3 項目
- [x] メニューの「開始」で実行が始まり、メニューが「停止」に変わり、トレイアイコンの波紋が緑になる。止めるとグレーに戻る
- [x] 実行中にトレイの「終了」を選ぶと、クリックが止まってからアプリが終了する
- [x] 実行中に × ボタンを押しても、クリックは止まらない（トレイに格納されるだけ）
- [x] 「ログイン時に自動で起動する」をオンにすると、Windows のスタートアップ（設定 > アプリ > スタートアップ）に auto-clicker が出る。オフにすると消える
- [x] 自動起動をオンにして再ログインすると、アプリが起動する
- [x] 「ウィンドウを出さずにトレイで起動」と自動起動を両方オンにして再ログインすると、ウィンドウなしでトレイにだけ出る
- [x] macOS: メニューバーにアイコンが出る。Linux (X11): appindicator があればトレイが出て、なければ × ボタンで終了する
